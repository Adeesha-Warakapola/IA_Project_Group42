# Q5: Corners Problem

`CornersProblem` represents a search state as `(position, visitedCorners)`.
`position` is Pac-Man's coordinate, and `visitedCorners` is a four-boolean
tuple aligned with `problem.corners`. The tuple is hashable, so search can
track expanded states without including the unchanged walls or game state.
The starting corner is marked visited when applicable. Each legal successor
moves one square, updates the visited tuple if it reaches a corner, and costs
one.

# Q6: Corners Heuristic

`cornersHeuristic` finds the shortest Manhattan-distance tour from Pac-Man's
current position through all unvisited corners, checking every permutation of
the remaining corners (at most 4! orders). Manhattan distance ignores walls,
so each segment is no longer than the corresponding real maze path. Therefore
the shortest such tour is a lower bound on the actual remaining path cost and
the heuristic is admissible.

The heuristic is also consistent: for a one-step move, the Manhattan distance
to a fixed corner changes by at most the step cost. If the move visits a
corner, the remaining tour can begin there; the triangle inequality shows
that removing this now-visited corner cannot make the heuristic decrease by
more than the one-step cost.

On `mediumCorners`, the farthest-unvisited-corner Manhattan heuristic expands
1,136 nodes. The shortest-tour heuristic expands 741 nodes, while finding a
106-step solution.
