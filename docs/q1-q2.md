# Q1: Depth-First Search

In `content/search/search.py`, I implemented graph-search DFS. Its fringe is a
`util.Stack` of states paired with the actions used to reach them, so recently
discovered successors are explored first. An expanded set prevents states from
being expanded repeatedly; successors already in that set are also skipped
when adding to the fringe. The check after popping is still needed because two
different paths can queue the same state before either copy is expanded. The
Q1 autograder passed all five tests, including the Pac-Man maze test.

# Q2: Breadth-First Search

In the same file, I implemented graph-search BFS with a `util.Queue`, keeping
the state/action path and expanded set used by DFS. The queue explores states
in arrival order, one depth layer at a time. When every move has the same cost,
the first goal removed from the queue has the fewest moves, so BFS finds a
shortest path. DFS uses a stack and may follow a long branch to a goal before
considering a shorter route. The Q2 autograder passed all five tests,
including the Pac-Man maze test.
